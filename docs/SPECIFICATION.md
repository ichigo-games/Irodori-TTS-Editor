# 彩エディター 仕様書

更新日: 2026-09-13  
対象: このリポジトリの実装（Post Processingのレビュー修正まで）

## 1. 名称・目的・範囲

正式な呼び名は **彩エディター**。既存の技術名は `Irodori-TTS-Editor`。フォルダ名、起動ファイル、API、`.irodori` 拡張子は変更しない。
Windowsローカル環境でIrodori-TTSを使用し、YouTubeナレーションを行単位で編集・生成・確認して、YMM4用WAV＋字幕txtとして出力する。
現在はFastAPIとブラウザによるWebアプリ。専用デスクトップウィンドウやインストーラーは未実装。Voice Design自体はこのエディターの機能ではない。

## 2. 構成・起動

固定版・試用版の起動プロファイルを追加（2026-09-14）。`start-stable.bat` / `start-latest.bat` から `run.py --profile stable/latest` を実行。環境作成と固定範囲は [ENVIRONMENTS.md](ENVIRONMENTS.md) を参照。既定起動の互換性を維持し、プロファイル起動時のみJSONからTTS・コード・データ・ポート・モデル保存先を切り替える。固定版モデル欠落時はダウンロードへフォールバックしない。

| 項目 | 現在の仕様 |
|---|---|
| 作業フォルダ | `E:\Irodori-TTS-Editor` |
| TTS本体 | 既定 `E:\Irodori-TTS`。`IRODORI_HOME`で変更可能 |
| Python | TTS本体の `.venv\Scripts\python.exe` を利用 |
| 起動 | `start.bat` または `start.ps1` → `run.py` |
| 接続 | `http://127.0.0.1:8765/` |
| データルート | 通常は作業フォルダ。`EDITOR_DATA`で分離可能 |
| UI | HTML / CSS / JavaScript。フロントエンドのビルド工程なし |
| 推論 | Irodori-TTS-v4.1-Small、CUDA。初回生成時にランタイムをロード |

ローカル用。外部公開は想定しない。Host制限・他Originからの変更要求拒否がある。TTS本体やその環境を無断で変更しない。

## 3. 画面

共通上部にプロジェクト選択（保存済みプロジェクトを更新日時の新しい順に表示。プロジェクト管理の更新日時と同じ基準）、新規プロジェクト、開く、保存、名前を付けて保存、その他（保存名・自動保存）、台本読込、プロジェクト管理を置く。新規・開く・保存・名前を付けて保存を隣接させ、台本読込・プロジェクト管理とは区切り線で分ける。

| タブ | 内容 |
|---|---|
| エディター | （上部のプロジェクト操作行の右側に「生成｜出力先を設定・出力・自動出力｜中断」を置く）出力先（表示のみ。プロジェクト保存先の下に「出力先：…」と表示し、「出力先を設定」でフォルダ選択）、出力ボタン（押すと全件／選択行のみを選ぶ）、自動出力スイッチ、生成ボタン（押すと対象を選ぶ）・中断、連続再生、行追加、行一覧 |
| 読み辞書 | 表記→読みの登録、有効/無効、削除、保存 |
| 設定 | Seed方式、マスター管理、共通音声、デフォルト話速、数字補正、字幕折り返し、Post Processing |
| 一括 | 選択行への話速・末尾無音の適用、選択数表示 |

タブ切替だけでは入力・行選択を破棄しない。行一覧は内部スクロール。タブは矢印・Home・Endキーでも切替可能。

## 4. 台本取り込み・行編集

### 台本

- txt: UTF-8（BOMあり/なし）、CP932、Shift_JIS。1行1セリフ。空行を除き、前後空白を除去。
- CSV: 同じ文字コードに対応。カンマ・改行を含むセルはCSV規則に従って引用する。
- 見出しあり: `セリフ` / `text`、`マスター` / `master`、`末尾無音ms` / `pause_ms`。列順は自由。セリフ列必須。重複・未知の見出しは拒否。
- 見出しなし: セリフ、マスター、末尾無音msの固定順（1〜3列）。先頭行もデータとして扱う。見出し判定は既知の列名との一致による。
- CSVの空セリフ行は読み飛ばす。未登録マスター、不正な無音値、列超過などは行番号付きエラー。
- CSVのマスター指定は登録名。英字の大小を区別しない。空欄または「共通マスター」は共通音声。
- 読込は新しい作業プロジェクトを作成する。既存行への追記ではない。

### 行

字幕、読み上げ、話速、指定Seed、マスター、末尾無音を編集できる。「あ」ボタンで実際のTTS送信文を確認する。
行追加はテキストエリアに入力し、「末尾に追加」ボタン（またはCtrl+Enter／Cmd+Enter）か「選択行の下に追加」ボタンで追加する。改行区切りで複数行を一度にまとめて追加でき、空行は無視する。「選択行の下に追加」は選択中の行（複数選択時は最後の行）の直後に挿入する、未選択では使用できない。追加後は新しく追加した行（複数行なら最後の行）を選択状態にするため、続けて「選択行の下に追加」を押すとそのまま下へ連続して追加できる。行削除・追加・移動で行番号を1から振り直す。行削除ボタンはGoogle Material Symbolsの「delete」SVGをローカル保存して表示し、出力アイコンと同じ20px・文字色に揃える。
クリック、Ctrlクリック、Shiftクリックで選択。全行選択あり。
左端「⋮」のドラッグで移動し、行の上半分/下半分で挿入位置を決める。連続した選択行は元の順序を維持してまとめて移動する。離れた複数行の一括移動は拒否。
移動では字幕・読み・音声・Seed・マスター・無音・履歴情報を保持する。WAVファイル名を行番号に合わせて変更しない。

### 初期値・範囲

| 項目 | 仕様 |
|---|---|
| 話速 `duration_scale` | 初期設定0.85、範囲0.25〜4、入力ステップ0.05。小さいほど短く速い |
| Seed | 空欄はrandom、固定値は0〜4294967295。実使用値は別に保存 |
| 末尾無音 | 0〜60000msの整数。上下操作は50ms刻み、手入力は整数単位 |
| txt取り込みの無音 | 設定の `default_pause_ms`（初期値200ms） |
| CSVの無音省略・空欄 | 設定の `default_pause_ms`。明示した0を含む指定値は優先 |
| エディターで新しく追加する行 | 設定の `default_pause_ms`（台本txt取り込みと同じ値） |
| 旧データの無音未設定 | 0ms |

設定の「新規台本の話速」の隣に「台本読込時の末尾無音（ms）」を置く。0〜60000msの整数、上下操作は50ms刻み。「設定を保存」で環境ごとのsettings.jsonへ永続保存する。次回のtxt/CSV読込・エディターでの行追加に適用し、既存行・保存プロジェクト読込には適用しない。旧設定は200ms、旧クライアントが項目を送信しない場合は現在値を維持する。

一括適用は選択した行だけが対象。全行変更したければ全行選択する。

## 5. 生成と再生成条件

「生成」ボタンを押すと選択ダイアログ（すべて生成／選択行を生成／キャンセル）が開く。選択行がなければ「選択行を生成」は押せない。「すべて生成」は生成済み以外（未生成・変更あり・エラー）の行がすべて対象（以前の「未生成を生成」と同じ動作）。「全行を再生成」ボタンは廃止した。全行を作り直すときは全行を選択して「選択行を生成」を使う（APIの `mode=all` は残す）。
「自動出力」スイッチ（出力ボタンの隣、ON/OFF）がONの間は、生成した行を1行生成し終えるたびに、その行だけを出力先へ自動で出力する。すべて生成・選択行を生成・行ごとの生成/再生成のすべてに適用し、出力するのはそのジョブで生成できた行だけ（生成失敗行と、既に生成済みの行は対象外）。スイッチの状態はブラウザに保存し（既定OFF）、生成中は切り替えられない。出力先が未設定のまま生成を始めると、まず出力先選択ダイアログを表示して生成開始前に確定する（キャンセル時は生成を開始せずメッセージを表示）。出力の内容・ファイル名・字幕・Post Processing・末尾無音は手動の出力と同じ処理で、サーバーが生成ジョブの中で行ごとに実行する。自動出力に失敗しても生成は継続し、完了時に失敗件数と原因を表示する。連続して出力する場合も手動出力と同じく1秒以上の間隔を空ける。生成中は手動の出力を受け付けないため、手動の出力は生成完了後に行う。
ジョブはプロセス内で1つ。行順に処理し、1行の失敗があっても後続を試す。
Seed方式は行設定、新しいランダム、前回と同じ。前回値がない場合はランダム。

「中断」ボタンは生成と出力の両方に使う。生成中（自動出力を含む）に押すと停止要求を記録し、処理中の行の生成・保存・自動出力が終わったら次の行へ進まず終了する。手動の出力中（全行・選択行）に押すと、公開中のWAV＋字幕txtの組を完成させたあと残りの行は出力せず終了し、出力済みの分は残す（応答の `stopped` が真、`count` は出力済みの組数）。どちらも即時キャンセルではない。完了分を保持し、「すべて生成」で残りを再開できる。中断はロックを待たずに要求するため、出力中でも押せる。
生成中は行編集・移動・プロジェクト操作等を制限するが、連続再生は操作可能。

| 変更 | 音声の再生成 |
|---|---|
| 読み上げ文、話速、指定Seed、行マスター | 必要 |
| 辞書・数字補正・共通音声 | 実際の送信文/参照音声が変わる生成済み行は必要 |
| 字幕のみ | 不要 |
| 行の順番 | 不要 |
| 末尾無音 | 不要 |
| 字幕折り返し | 不要 |
| Post Processing | 不要 |

状態は `pending / generating / generated / stale / error`。旧WAVは変更あり状態でも保持。前回の生成中断・ファイル欠落は読込時にエラーへ戻す。

## 6. テキスト・音声の処理順

```text
読み上げ文 → 読み辞書 → 数字正規化 → TTS → 元WAV
元WAV → Post Processing（有効時）→ 末尾無音追加 → 試聴 / 出力WAV
字幕文 → 自動折り返し（有効時）→ 出力txt
```

辞書は長い表記を優先した一度の置換で、置換結果を連鎖置換しない。数字正規化は `app/preprocessing.py` が定義する範囲で実施する。入力欄・字幕は書き換えない。

### 字幕折り返し

出力txtの書き出し直前だけ適用。30文字以内はそのまま。超えた場合は中央±5文字で自然な区切りを探し、中央に近い候補を優先。同距離なら句読点を優先する。候補がなければ文字種境界、最後に中央に近い安全な位置を選ぶ。
自動改行は最大1つ。手動改行を保持。数字・英数字のまとまりやカタカナ語の途中を避け、安全に分割できない単一トークンは1行のまま。形態素解析ではない。

### 末尾無音

元WAV末尾への追加時間。既存の無音を検出・除去したり、合計無音を指定値に揃える処理ではない。元WAVは変更せずキャッシュを作る。変更を繰り返しても無音は累積しない。

### Post Processing

全プロジェクト共通設定。全体の初期値はOFF。非破壊でキャッシュ生成する。

| 設定 | 初期値 / 範囲 |
|---|---|
| EQ | ON、プリセット「耳当たりを柔らかく」 |
| 中心周波数 | 3500Hz / 20〜20000Hz |
| ゲイン | −1.5dB / −12〜+12dB |
| Q | 1 / 0.1〜10 |
| Peak制御 | ON、−1dBFS / −24〜0dBFS |

プリセットは「なし」（EQゲイン0）・「耳当たりを柔らかく」・「カスタム」。EQの後にPeak制御。Peak制御はサンプルピークを超えた音声全体を減衰する方式で、コンプレッサーやTrue Peakリミッターではない。弱い音を持ち上げない。
保存した設定を試聴と出力に適用する。補正前/後の比較試聴あり。後の試聴は全体ON/OFFにかかわらず個別のEQ/Peak設定を使う。
保存時は連続再生・比較試聴を停止し、音声URLへ設定識別値を含めて古い音声を再利用しない。プリセット固定値は定期更新で編集可能に戻さない。旧保存値がプリセット名と不一致なら実値を保ってカスタム表示する。

## 7. 連続再生

選択なしなら先頭、選択ありなら最初の選択行から末尾まで。選択行だけを再生する機能ではない。
▶で開始/再開、■で位置を保持して一時停止。行送りで現在行を選択・スクロールする。
生成中の対象行は完成まで待機。生成対象外で再生できない行はスキップ。中断後の未完成行もスキップする。
手動選択変更、プロジェクト切替、生成開始、行削除、無音変更、個別音声再生、補正設定保存などでは再生位置をリセットする。再読込後の位置復元はない。

## 8. YMM4出力

- 各行の生成/再生成ボタンとゴミ箱の間にGoogle Material Symbolsの「output」SVGアイコンを置く（ローカル保存・文字色に追従）。この行だけのWAV＋字幕txtを出力する。選択行・選択行は変更しない。出力先、フォルダ選択、音声加工、字幕処理、ファイル名、非上書きは通常出力と共通。生成中は使用不可。対象行が未生成・変更あり・エラーなら既存の出力APIで拒否する。

- 出力ボタンを押すと確認ダイアログで「全件を出力」「選択行のみ出力」「キャンセル」を選ぶ（出力対象のプルダウンは廃止。選択行がなければ「選択行のみ」は押せない）。対象に未生成・変更あり・エラーがあれば拒否。
- 指定フォルダ直下に出す。中間フォルダを作らない。
- GUIで出力先が空ならWindowsフォルダ選択。キャンセルなら出力しない。
- ファイル名例: `001_20260913_123456_78_seed12345.wav` と同名の `.txt`。
- 行番号、ローカル出力日時、小数秒2桁（10ms）、実使用Seed。旧データでSeed不明ならunknown。
- 1回の出力内は共通日時。衝突時は10msずつ進めて未使用名を選ぶ。
- 行順に出力。字幕txt（UTF-8 BOM）を完成させ、コピー済み一時WAVを正式名にして公開する。次の行まで1秒待つ。
- 自動出力（§5）も同じ出力処理（ファイル名・字幕先行・1秒間隔・既存ファイル非上書き・保護フォルダ拒否）を使い、1行ずつ出力する。
- YMM4の取り込み完了を直接確認する仕組みではない。失敗時は出力済みの一部が残ることがある。
- 既存出力を上書き・自動削除しない。設定変更・移動は出力済みファイルに反映されないため再出力が必要。
- TTS本体とエディター作業データの保護対象フォルダへの出力を拒否する。

## 9. 保存・マスター管理

### 試用版から通常版への読み取り専用参照

`EDITOR_SHARED_DATA` に通常版のデータルートを指定すると、通常版の読み辞書とマスター登録を参照する。共有元とローカル保存先が同一の場合は起動を拒否。通常版の辞書が未作成の場合は空辞書、共有元settingsの欠落・破損時はHTTP 503で処理を止める。試用版の辞書保存・マスター新規登録・共有マスターの改名/削除はUIとAPIで禁止する。通常版自体の動作は変更しない。

共有マスターは `shared:` 接頭辞のIDで試用版のローカル登録と区別し、音声をコピーせず元のパスから読む。行への割当と共通マスターへの適用は可能。共通マスターの選択・話速・数字補正・音声補正は試用版のローカル設定として保存し、共有登録一覧は保存しない。通常版の設定全体や共通マスター選択を自動同期するものではない。

通常版で保存した辞書・登録の変更は次回HTTP要求で取り込み、画面では約1.8秒ごとのポーリングで反映する。生成中は取り込みを保留し、ジョブの辞書・参照条件を維持する。共有音声ファイル自体を外部で変更・削除しないこと。通常版での使用判定には試用版のプロジェクトは含まれず、通常版で登録削除すると試用版では未登録扱いになる。

`.irodori` 保存には使用中の共有マスター音声を同梱する。再読込では内容一致する共有登録を再利用し、共有元にない同梱音声は試用版ローカルに取り込む（そのローカル登録は編集可能）。試用版から通常版のデータルート内へのプロジェクト保存・出力は拒否する。ただし、その配下に配置された試用版の `EDITOR_DATA` 内は通常の保存/出力制限に従って利用できる。

検証: `python -B -m unittest tests.test_shared_library tests.test_manual_save -v`。

既定は手動保存。新規・台本読込・プロジェクト読込はOSの一時領域の作業コピーで編集し、明示保存するまで `projects` の保存一覧に追加しない。既存の保存スナップショットも通常編集では更新しない。「保存」で指定した `.irodori` と一覧用スナップショットを更新する。同じ保存先は同じ一覧項目を更新し、名前を付けて別の場所へ保存すると別項目になる。
`.irodori` はZIPで、プロジェクトJSON、元生成WAV、使用するマスター音声を含む。辞書、Post Processing等の全体設定は同梱していない。異なる全体設定で開けば送信文や出力音が変わり得る。
開くと新しい内部作業プロジェクトを作る。同梱マスターは内容のSHA-256で既存登録と照合し、同じID、同名、その他一致音声の順で再利用する。ID/名前が同じでも音声内容が違えば別登録。同じファイルを開き直すたびに登録を増やさない。

マスターは登録名・元ファイル名・保存先を区別する。コピー先の内部ファイル名はUUIDの場合がある。古い登録には元名がない場合がある。登録名変更、共通設定への適用、使用プロジェクト/行数確認、未使用登録の削除に対応する。
削除は登録解除でWAV本体を残す。共通または行で使用中の登録を拒否。既にできた重複登録の自動整理機能はない。

## 10. 選択ダイアログ

台本、共通マスターWAV、登録マスターWAV、プロジェクトを開く、名前を付けて保存、出力先はそれぞれ前回のフォルダを記憶する。`dialog_locations.json`へ永続保存。キャンセルで更新しない。記憶先が存在しなければ通常の初期場所へ戻る。
記憶キーはボタン別の固定ID（script / voice / master / project_open / project_save / output）。旧形式の「種別＋タイトル」の履歴も引き継ぐ。記憶先を優先し、存在しなければ呼び出し元の初期フォルダ、それも無効ならアプリのフォルダを開く。Windowsダイアログへは絶対パスをスラッシュ区切りに正規化して渡す。

## 13. 制約と今後の検討

- デスクトップアプリ化は検討段階。現行仕様に混ぜて実装済みと扱わない。
- Post Processingは共通設定で、プロジェクト固有保存は未対応。
- 加工キャッシュの容量制限・自動掃除、重複マスター整理、Undo/Redoは未実装。
- 生成・出力・加工には共有ロックがある。長い処理中の応答性とロック範囲に注意する。
- APIテストだけではブラウザのキャッシュ・音声状態やYMM4の取り込みを保証できない。

開発時のルール・確認手順は [DEVELOPMENT.md](DEVELOPMENT.md) を参照。

## 14. プロジェクト管理・参照音声の独立保存

上部「プロジェクト管理」で名前・行数・更新日時・ID・保存ファイルを確認し、作業プロジェクトをゴミ箱へ移動・復元できる。Windowsのゴミ箱ではなくデータルート内の `trash/<id>` を使用する。完全削除は提供しない。ゴミ箱内は通常のプロジェクト選択から除外する。外部の `.irodori` と出力済みWAV/txtは操作しない。復元先IDが存在する場合は上書きせず拒否。生成中の移動・復元は拒否する。

読み込んだマスターの新規登録先は `voices/shared/<SHA256>.wav`。起動時とゴミ箱移動前に、projects/trash内を参照する共通音声・登録マスター・行の生成時参照をここへコピーし、参照を更新する。移行前JSONは `.before-voice-migration.bak` として保存し、元音声も残す。同じ内容の参照先変更だけで生成済み音声をstaleにしない。参照音声欠落などで移行が完了できない場合はゴミ箱移動を拒否する。起動時の失敗はターミナルへ表示し、アプリ自体は起動する。ゴミ箱内の行もマスターの使用判定に含め、復元に必要な登録を削除させない。

API: GET `/api/project-management`、POST `/api/projects/{pid}/trash`、POST `/api/projects/{pid}/restore`。実装は `app/project_management.py` と `app/static/project_management.js`。検証: `python -B -m unittest tests.test_project_management`。

## 15. 手動保存を既定とする作業ライフサイクル

- 新規・台本読込・保存ファイル読込は一時作業コピー。作業用JSONと生成音声は必要だが、保存済みプロジェクトとして自動登録しない。
- `.irodori` へ明示保存したものだけ `projects` に保存スナップショットを保持。以前からあるprojectsデータは自動削除しない。
- 未保存の変更を画面上部に表示。プロジェクト切替・新規・読込前に保存するか確認し、保存キャンセル時は切替しない。保存しない場合は破棄するか改めて確認する。タブ/画面を閉じる際はブラウザ標準の未保存確認を要求する（ブラウザの制限に従う）。
- 保存オプション「保存済みファイルを自動保存」は既定OFF。保存先のあるプロジェクトのみONにでき、その作業中だけ有効。画面を開いていて生成中/入力中でないとき、約3秒ごとに変更を確認し保存する。再度プロジェクトを開くとOFF。ブラウザ終了後の自動保存はない。
- 一時作業領域は `tempfile.TemporaryDirectory` に保持し、通常のサーバー終了時に削除。作業切替で破棄を確定した旧領域も削除する。異常終了ではOS一時領域に残る場合があるが、保存一覧には載らない。未保存内容のクラッシュ復旧は保証しない。
- 生成中の変更は作業コピーのみ。保存・自動保存は生成完了/中断後に行う。辞書・音声補正などの全体設定は従来どおり各設定の保存で永続化され、プロジェクト手動保存とは別。
- API追加: POST `/api/projects/{pid}/open-saved`、POST `/api/projects/{pid}/close`、PUT `/api/projects/{pid}/autosave`。`dirty / autosave / catalog_id` は作業管理情報。実装は `app/working_sessions.py`。テストは `tests/test_manual_save.py`。
- プロジェクト選択プルダウンは常に現在編集中の作業コピーを選択状態にする。作業コピーIDが保存一覧（カタログ）のIDと一致しない場合は「（作業中）」の一時項目を追加して選択する。新規作成・台本読込・「開く…」・保存・名前を付けて保存のいずれの後も、この反映を行う。

## 16. HP関連の組み込み読み補正

TTS送信文を作る際、辞書で指定されていない部分の `HP / 低HP / 高HP / 現在HP / HP割合` を、それぞれ `エイチピー / テイエイチピー / コウエイチピー / ゲンザイエイチピー / エイチピーワリアイ` に変換する。字幕・元台本・読み上げ入力欄は変更せず「あ」の読み確認と生成に同じ処理を使う。半角/全角のHPと小文字にも対応し、URL・ファイルパス・英単語内部は対象外。

ユーザー辞書の一致部分と置換結果を優先し、その部分にはHP補正を再適用しない。数字補正は従来どおり辞書適用結果にも適用する。HP補正は数字補正ON/OFFとは独立して常時適用する。既存生成済み行の送信文が変わる場合は「変更あり」となり、反映には再生成が必要。台本読込だけでなく行追加・読み編集にも有効。


## 17. 数量・スキル番号の漢数字補正

数字補正ON時、整数＋「ターン・体・回・人・個・倍・ダメージ・連撃・つ・発・時・分・秒・階・枚・円・%・％」を漢数字へ変換し、単位・記号は保持する。例：`6ターン → 六ターン`、`1920%×3体 → 千九百二十%×三体`、`2つ → 二つ`、`3発 → 三発`、`2連撃 → 二連撃`。桁区切りは3桁単位のみ受け付ける。

`S / スキル / パッシブ / Lv / レベル` に直結する整数も漢数字にする。接頭辞は入力どおり保持し、`S1 → S一`、`スキル１ → スキル一`、`パッシブ２ → パッシブ二`、`Lv240 → Lv二百四十`。半角・全角数字およびS/Lvの英字大小・全角に対応する。小数のラベル番号（Lv1.2など）は変換しない。

小数の読みは従来どおり（`1.05倍 → いちてんゼロご倍`、`3.5% → さんてんごぱーせんと`）。小数＋ターン/体/回/人/個/連撃/つ/発/時/分/秒/階/枚/円は従来どおり変換しない。単独整数・第N章など今回の対象外は従来の読み補正を維持する。0〜999999999を対象とし、先頭ゼロ付き番号・範囲外・型番・URL・ファイルパスは保護する。

入力欄と字幕は変更せず、読み確認とTTS送信文だけを補正する。数字補正OFFなら漢数字補正も無効。既存音声への反映には再生成が必要。聴感の改善は使用マスターによって異なり、テキスト変換テストでは保証しない。
