# 彩エディター 開発ガイド

更新日: 2026-09-13

## 共通の参照先

Codex・Claudeとも、作業前に [SPECIFICATION.md](SPECIFICATION.md) の対象機能を読む。
ユーザーの最新の指示を優先する。仕様とコードが違う場合は、差異を明示して意図を確認または調査する。古いREADMEの追記や過去の会話を、現行仕様より新しいものと決めつけない。
仕様書は実装のスナップショット。機能を変えたら同じ作業で更新する。

## 変更の原則

- 会話・ドキュメントでは「彩エディター」。既存パス・保存拡張子・APIを名称変更だけで移行しない。
- 作業開始時に `git status` と差分を確認し、別の作業者の変更を消さない。共通ファイルを同時編集する場合は担当を調整する。
- TTS本体 `E:\Irodori-TTS` とそのPython環境を変更しない。ランタイムやモデルは `app/tts.py` の境界で扱う。
- ユーザーの台本、設定、辞書、プロジェクト、参照音声をテスト用に書き換えない。テストは `EDITOR_DATA` で分離する。
- raw音声を加工で上書きしない。字幕・読み・元台本を混同しない。
- 行番号は可変。行移動/削除でWAV参照と設定を保持し、新規生成が他行のWAVを上書きしないことを確認する。
- マスター読込は内容一致で再利用する。登録削除と物理削除は別操作。
- 生成停止は現在行の完了後。GPU処理の強制終了へ勝手に変更しない。
- 出力先直下、字幕先行、完成WAVの公開、1秒間隔、既存ファイル非上書きを維持する。
- 試聴と出力の加工経路を共有する。設定が変わる音声URLにはキャッシュ識別値を含める。
- 定期ポーリングで入力値・選択状態・再生位置・プリセットのdisabled状態を意図せず破壊しない。
- 静的ファイルを変えたら必要に応じてindex.htmlのURL版識別子を更新する。
- 保存形式変更では旧プロジェクト、同じ保存ファイルの再読込、マスター未登録・欠落を確認する。

## 検証

作業フォルダで実行する。

```powershell
& E:\Irodori-TTS\.venv\Scripts\python.exe -B -m unittest discover -s tests -v
node --check app/static/app.js
node --check app/static/playback.js
node --check app/static/row_drag.js
node --test tests/test_playback.cjs tests/test_row_drag.cjs tests/test_post_processing_ui.cjs
```

変更に応じて対象テストを先に実行する。今回のドキュメント整備時に全テストを再実行したという意味ではない。
既存の一部テストは疑似WAVを使う。無音付き処理を通るとFormat not recognisedになる既知の失敗が以前にあった。テストの現在の結果と原因を確認し、未実行や失敗を成功扱いしない。新しい音声処理テストには有効なPCM WAVを使う。

| 変更箇所 | 必須の確認観点 |
|---|---|
| テキスト処理 | 辞書順序、数字、字幕のみの変更、手動改行、中央折り返し |
| 生成 | 失敗後継続、前回Seed、中断と残り再開、元音声保持 |
| 再生 | 開始/一時停止/再開、完成待ち、中断後、手動選択、設定保存後の更新 |
| 行移動 | 単行/連続複数、上下・末尾、無操作、非連続拒否、音声参照維持 |
| 出力 | 並び順、1秒待機、字幕先行、WAV完成前に公開しない、衝突、選択のみ |
| 保存/マスター | 再読込で増殖しない、同名別音声、使用中削除拒否、旧データ |
| ダイアログ | ボタン別記憶、再起動、キャンセル、存在しない前回フォルダ |
| Post Processing | raw不変、EQ/Peak、試聴と出力一致、設定変更、プリセット表示と保存値一致 |

UI変更は可能なら実ブラウザでも確認する。GPU推論・Windowsダイアログ・YMM4連携・聴感評価をモックテストで確認済みと報告しない。

## 引き継ぎ・完了報告

変更内容、目的、実行した確認と未確認部分、既知の問題、必要な反映操作を簡潔に記録する。
Python変更は通常サーバー再起動が必要。静的UIだけの変更は通常ブラウザ再読み込みで反映。ユーザーの生成中プロセスを無断で停止しない。
仕様を変えたらSPECIFICATION.mdを更新する。READMEは起動案内と仕様書への入口にし、同じ仕様の矛盾した追記を増やさない。

手動保存の検証は `python -B -m unittest tests.test_manual_save`。新規/読込時の一覧非増殖、保存前後の差、破棄、保存キャンセル、別名保存と同一保存先の更新を確認する。編集処理からDATA/projectsへ直接書き込まず、project_path経由で一時作業コピーを扱う。
